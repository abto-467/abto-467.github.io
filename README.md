# Abto-467的个人网站 · 部署说明

这是用 GitHub Pages 搭建个人主页的完整文件包，纯静态、零依赖。

风格：**简约 + 液态玻璃（Liquid Glass）**，浅色主题。

## 导航结构

- **顶部胶囊导航**（所有尺寸都在）：左侧姓名，右侧栏目链接。当前栏目背后有一块白色"滑动指示块"，切换栏目时会平滑滑过去；胶囊底部有一条 2px 的滚动进度条。
- **悬浮 Dock**：宽屏（≥1200px）固定在右侧竖排，窄屏自动变成底部横条。图标 + 悬停文字提示。上面那枚选框**跟着页面下滑连续滑动**，停在"视口 34% 处"所在的栏目上；点某个模块会先把它**钉住**，你再自己滚动时松开。

## 动效清单

| 动效 | 说明 |
|------|------|
| 标题碎片化 | 首屏标题由一万五千个碎片拼成。打开时**先完整可读**，1.5 秒后**慢慢碎成微粒**；光标回到标题位置就**迅速聚拢**回文字；页面往下滚时，这团微粒**汇聚成背景里的 `ABTO`**，并**一直钉在视口正中**、淡成一层水印（详见下方专节） |
| 背景光斑被推开 | 指针靠近时，背景色块会被"挤开"，离开后带惯性缓缓归位 |
| 背景点击涟漪 | 点击任意位置，从落点扩散一圈柔光（一次性，不是拖尾） |
| 栏目色相漂移 | 滚到不同栏目，整个背景的色相平滑偏一点，氛围跟着换 |
| 指针光感跟随 | 鼠标移到任何**非背景**的东西上——导航胶囊、按钮、标签、徽标、Dock、各玻璃面板——表面都有一团**柔白的光**跟着光标走。它是**单色的、由中心向外单调衰减**，没有彩色光圈，看上去就是"光标那里有一盏灯" |
| 折射边 | 面板没有描边，边缘是一圈 **140° 的冷光渐变**（左上偏冷蓝 → 右下更淡的冷蓝），像光穿过玻璃时的色散。**只能是冷色**——加暖色/粉色会被看成"红框" |
| 真实折射 + 色散 | 每块玻璃背后生成一张**圆角矩形透镜的位移向量图**，用 SVG `feDisplacementMap` 把背景按它扭曲：**边缘的背景被"掰弯"、中心保持清晰**；R/G/B 三条通道用三档位移强度各折射一次再叠回，边缘出现**色散**（颜色被拆开）。Chromium 系浏览器启用，其余自动回落到 `blur(0px)`（详见下方专节） |
| 玻璃果冻变形 | **滚动越快，玻璃面板沿运动方向被轻微拉长、横向微压**（最快约 5%），停下后平滑弹回；Dock 选框移动时的速度形变同理但更明显（15%）。都写在独立属性/JS transform 上，不和倾斜、入场动画打架 |
| 虚拟光感 | 页面顶部有一束光、每块玻璃带柔光光晕、上缘有一道漫射内高光 |
| 导航栏底部模糊 | 顶部导航下方 150px 有一整片磨砂层，向下渐隐，内容滚过时被磨掉 |
| 3D 倾斜 | 卡片随指针小幅倾斜（`data-tilt` 控制幅度），CSS 过渡让回弹有阻尼感 |
| 背景漂移 | 5 个模糊色块缓慢游动，玻璃才有可折射的层次；滚动时还有视差 |
| 按钮点击涟漪 | 点击按钮时从落点扩散一圈光。**按钮本身不会跟着光标位移**（磁吸已去掉） |
| Dock 悬浮选框 | Dock 底座是圆头胶囊；上面浮着一枚**形状一致、完整液态玻璃**的选框，并且**跟着页面下滑连续滑动**（不是到阈值才跳一格）。滑动中它**沿运动方向拉伸、垂直方向压扁**，速度越快形变越明显，同时整体略微放大；停下约 0.4 秒收回。**点击导航则是 480ms 的补间滑过去**并钉住那一格，你自己一滚动就松开、改回跟着页面滑。选框是一扇"小窗"，窗内是同一批图标的副本，所以**窗口扫到哪个图标，哪个图标就变蓝** |
| 逐个入场 | 滚动到视口时元素依次淡入；技能芯片一个一个弹出 |
| 导航滑动块 | 顶部指示块与 Dock 高亮块的位移过渡 |

## 三步部署（推荐用网页拖拽，最省事）

1. **登录 GitHub**，点右上角 `+` → **New repository**
2. **仓库名必须填**：`你的用户名.github.io`
   （例如用户名是 `zhangsan`，仓库名就填 `zhangsan.github.io`）
   可见性选 **Public**，点 **Create repository**
3. 进入仓库 → **Add file → Upload files** → 把 `index.html` 和 `.nojekyll` 一起拖进去 → **Commit changes**

等 1~2 分钟，访问 `https://你的用户名.github.io` 就能看到网站了。

> ⚠️ `index.html` 上传时注意别变成 `index.html.txt`；`.nojekyll` 是隐藏文件，macOS 上传前按 `Cmd+Shift+.` 可显示。

## 背景互动怎么调

- **推开力度**：JS 里 `f = f * f * 54;` 的 `54`（最大推开像素），`s.w * 0.75 + 180` 是影响半径
- **跟随快慢**：`s.ox += (tx - s.ox) * 0.075;` 的 `0.075`，越大越跟手，越小越"重"
- **点击涟漪大小**：CSS 里 `.bg-rip` 的 `width/height`（当前 760px）
- **栏目色相**：JS 里的 `var HUE = {top:0, about:-9, ...}`，数字是 `hue-rotate` 的角度

## 首屏标题的碎片化怎么调

标题在 HTML 里仍然是**一整句真文本**（`<h1>你好，我是 <mark>Abto-467</mark></h1>`），SEO / 读屏 / 禁用 JS 都正常（禁用 JS 时就是一行普通标题，已验证）。JS 可用时会把 h1 透明掉（保留布局与语义），改由一张画布在上面画碎片 —— 位置是把标题渲染到离屏画布后**逐像素采样**得来的，所以改文案不用改任何参数，采样会自动跟着变。

标题下面**没有小字副标题**了（原来那行 `.sub` 已删掉）。

画布是 **`position:fixed`、铺满整个视口**（不是只盖 hero），由此有两条必须知道的结论：

1. 碎片可以飘出标题行、飘到任何地方；
2. 汇成的 `ABTO` 用的是**视口中心**坐标，所以往下滚时它**始终钉在背景正中**，不会跟着文档跑掉；而标题那团字的"家"位置用 `titleDocY - pageYOffset` 算出来，粒子会**跟着标题一起往上滚**。

整个过程是**一条连续的时间线**，不是几个独立状态：

| 阶段 | 什么时候 | 表现 |
|------|----------|------|
| ① 可读 | 打开页面后的 `hold` 秒内 | 名字完整可读，形状就是那行标题 |
| ② 慢慢分裂 | `hold` 秒之后（光标不在标题上） | 碎片按各自的随机半径慢慢飘开，**字形被打散**，只剩一团微粒 |
| ③ 触碰汇总 | 光标回到标题原来的位置（外扩 24px 也算） | 所有微粒迅速聚拢，重新拼出"你好，我是 Abto-467" |
| ④ 汇聚成 ABTO | 页面往下滚，滚过 `hero` 高度 × `scrollSpan` | 这团微粒**直接**汇聚成视口正中的 `ABTO`（不会先拼回字形再飞走），并同时**淡成一层水印** |
| ⑤ 触碰分散 | 光标划过已汇成的 `ABTO` | **被光标碰到的微粒沿径向被推开**，光标挪走就弹回原位；只有光标附近的一圈受影响（`repR` 半径内），力随距离平方衰减，每个微粒还有随机系数 `fk`，推得参差错落。标题态下不生效，不会和 ③ 的"悬停聚拢"打架 |

> ④ 的字母和标题共用同一套 `TITLE_FX` 参数，**只有不透明度是分开的**：标题态用 `alpha`（.96，得看清），汇成字母后线性渐变成 `alphaBg`（.40）—— 因为它会长期停在正文后面，太实就压住文字了。渐变是按 `p`（汇聚进度）在 `frame()` 里逐帧算的。

**ABTO 是背景，不许盖住正文**（第 23 轮）：标题画布是 `position:fixed; z-index:0`，而 `main>section` 统一提到了 `z-index:1` —— 定位元素若不处理会画在静态内容之上，水印就会浮到正文上。改层级时记住这个顺序：`.bg`（色块，-1）< 标题画布（0）< 各内容区块（1）< header（60）< Dock（70）。画布在玻璃面板的 backdrop 里，所以 ABTO 经过面板时**会被折射**，和背景表现一致。

**颜色**：标题和所有粒子都是**蓝 → 青的渐变**（`#3f6ae0 → #7b8cf2 → #2f6bff → #5aa8ff → #00b8a9`），不再用黑色。`<h1>` 本身的 `color` 也同步改成 `#3f6ae0`，所以禁用 JS 时看到的也是蓝色标题。改渐变的位置是 `sampleTitle()` 里的那 5 个 `addColorStop`。

调手感就改脚本里那个 `TITLE_FX` 对象（在 `<script>` 里搜 `TITLE_FX`）：

- **`target`** —— 往下滚之后要汇聚成的那几个字母。**改这一处就行**，别的都不用动。
- `scale`：目标字母字号 = 标题字号 × 这个倍数（当前 1.75）
- `count`：碎片数量（当前 15000，宽度 <700px 时自动减半）。**密度要满足"相邻微粒互相压住"**，否则笔画会显成一串分开的点（沿笔画看像在"编织"）；嫌卡就调小
- `dot`：单块碎片边长（当前 2px）。越小越细腻，但要同步调大 `count` 才不会露缝
- `alpha`：标题态不透明度（当前 .96）
- `alphaBg`：汇成 ABTO 后的不透明度（当前 .40）。**它是常驻背景水印**，压太低看不见、太高会盖住正文
- `hold`：打开后名字先完整亮相多久（秒，当前 1.5）
- `spread`：碎裂时单个微粒的最大漂移（px，当前 84 —— 第 25 轮用户要"更散"）
- **散开和收回是两个独立的速率**（第 16 轮拆开，因为用户要"散开放慢、汇聚大幅加快"；第 25 轮又要求"运动更快"，eSpread 翻倍）：
  - `eSpread`（当前 .022）—— **散开**时 `spread01` 每帧逼近 1 的比例（约 3.5 秒散完）
  - `eGather01`（当前 .16）—— **悬停收回**时 `spread01` 每帧逼近 0 的比例。越大收得越快（当前约 0.3 秒回到字形）
- `eGather`：微粒飞回原位的缓动（当前 .5，越大越跟手）
- `eDrift`：漂浮抖动的缓动（当前 .012）
- `eScroll`：滚下去飞向 ABTO 的缓动（当前 .3，越大越快）
- `scrollSpan`：滚过 `hero` 高度的这个比例后完全变成字母（当前 0.5 → 约 307px）
- **ABTO 触碰分散**（滚下去之后，光标划过字母时把碰到的微粒推开）：
  - `repR`：作用半径（当前 95px）。越大，一圈被推开的范围越大
  - `repPush`：最多推开多远（当前 30px，初版 64 被嫌"太分散"）。推力 = `((1 - 距离/repR))² × repPush × 汇聚进度 × 每微粒随机系数`
  - 只在汇聚进度过半（p > .5）后生效，并随进度淡入 —— 标题态下光标仍是"聚拢"触发，两者不冲突
  - 光标位置在 `pointermove` 里记进 `pmx/pmy`；`pointerleave` / 窗口失焦会关掉（`ptrActive=false`），微粒弹回

五个实现要点，改的时候别踩：

1. **画布本地原点在左上角**。画布现在是 fixed 全视口，`cr.top` 恒为 0，所以画布坐标 == 视口坐标。
2. **粒子的"原位"必须逐帧跟 h1 的实时矩形走，不能用 build 时记下的坐标。** 原来用 `titleDocY`（build 时记的文档坐标）换算，但 `.hero-titlebox.reveal` 入场时有 `translateY(22px)`，字体/布局变化也会挪动标题 —— build 之后这些都过期，结果**粒子聚的地方和标题真的地方对不上，光标移上去"无法汇聚"**。现在每帧 `homeDy = liveRect().中心y − titleOy`（`liveRect()` 有 120ms 缓存 + 滚动时强制刷新），页面因为任何原因动了都严格贴合。
3. 碎片颜色按 4bit 量化进调色板并**按颜色排序**，绘制时只在颜色变化时改 `fillStyle`。不这么做的话，每帧一万多次 `fillStyle` 赋值会掉帧。
4. 采样**不能用等间距取点**（`i += stride` 那种），否则笔画上会出现规则的斜纹理/摩尔纹；现在是先把所有墨点索引洗牌（Fisher-Yates）再随机取，并加一点点亚像素抖动。
5. **碎裂方向必须完全随机。** 每个微粒在建立时就定下自己的**随机角度 + 随机半径**（`rx/ry = cos/sin(ang) × (8 + random^0.7 × spread)`），散开时沿各自的方向朝外飘 `position = 原位 + 落点 × spread01`。**不要用"统一的正弦/余弦振荡"来表达散开** —— 那会让方向之间产生相关性（x 用 `sin`、y 用 `cos` 且参数挂钩时尤其明显），看上去就像"整片字往一个方向跑"。另外每个微粒有**两条互相垂直、频率/相位/幅度全部各自随机**的抖动轴（`wd/wd2`、`fr/fr2`、`ph/ph2`，第 25 轮为"突出无序运动"从单轴升级），叠加出利萨茹式的乱窜轨迹。散开后**看不出原来的字形**——这是刻意的，不用去"保持字的样子"。
6. **散开↔聚合的模式切换必须缓变，不能硬切。** `hover` 翻转的那一帧，如果速率（`.011 ↔ .16`）和缓动系数（`.012 ↔ .5`）直接跳到新值，微粒会"猛地一窜"，衔接非常生硬（第 17 轮反馈）。现在是 `curRate` / `curE` 两个状态量逐帧逼近目标（`* .14` / `* .12`），切换变成"加速滑入"。另外**抖动幅度也要随 `spread01` 淡出**（`× Math.min(1, spread01×14)`），否则聚合收尾那一帧抖动会"啪"地消失。逐帧包围盒验证：hover 后宽度增量 `Δ9 → Δ36 → Δ24 → Δ9 → 0`，起手小、中段快、收尾缓。

另外：**触屏设备（无 hover）和「减少动态效果」下整个碎片系统不启用**，标题就是普通文本。

## 首屏留白（标题上下空间）

标题往上（徽标）和往下（两个按钮）的间距，都是靠 `.hero` 的 `padding` 撑出来的，并按屏幕宽度分档：

| 断点 | `padding` |
|------|-----------|
| 默认 | `84px 0 134px` |
| ≥1000px | `104px 0 156px` |
| ≥1366px | `118px 0 170px` |
| ≤680px | `68px 0 104px` |

- 徽标「机械设计与自动化 · 2025级」**已整行删除**（第 23 轮用户要求，`.badge` 的 CSS 也一并清掉了）；
- 标题与按钮之间靠 `.hero h1{margin-bottom:78px}`（原来是 46px，第 14 轮用户要求"两个按钮再往下移一点"）；
- **想让标题周围更松，优先加大 `.hero` 的上下 `padding`**，别去动 `margin`，否则容易把垂直居中挤偏。如果只是想让**按钮**更往下，改 `.hero h1` 的 `margin-bottom` 就行（只影响标题与按钮之间）。

**首屏那几块玻璃不再单独调透明度**：原来 `.hero .glass,.hero .btn.ghost` 有一层"再透一点"的覆盖，第 16 轮全局白底已经降到几乎全透（10%/2%/6%），覆盖反而比全局更"实"，所以删掉了 —— 现在首屏和全站用同一套 `--glass-bg`。

## Dock 的选框怎么调

底座（`.dock`）本身不动，浮在上面的两样东西跟着当前栏目走：

| 元素 | 作用 |
|------|------|
| `.dock .blob`（`#dockBlob`） | 那枚**完整液态玻璃**的选框：`--glass-bg-strong` + `backdrop-filter` + 1px `--glass-rim` + `--glass-inner`，圆角 999px |
| `.dock-tint`（`#dockTint`） | 蓝色层。一扇 `overflow:hidden` 的小窗，里面塞的是**同一批图标的副本**（JS 从真图标 `cloneNode` 过来） |

**"扫到哪个图标哪个变蓝"是怎么做到的**：`#dockTint` 移到目标图标的坐标，但内层 `#dockTintInner` 做**反向平移**（`translate3d(-x,-y,0)`），于是副本留在原位、和真图标严丝合缝地重叠。窗口只露出目标那一格，所以只有它显示蓝色描边（颜色就是 `var(--accent)`，**不再是炫彩渐变**）。

### 选框怎么"走"

它**跟着页面下滑连续滑动**，而不是到了栏目阈值才跳一格：

- 每个图标有一个**滚动锚点** `dockAnchors[i]` = 该栏目 `offsetTop - 视口高 × 0.34`（也就是"栏目顶部对上视口 34% 那条探测线"时的 `scrollY`）；第一个图标（首页）锚点是 0，**最后一个锚点钉在"滚到底"**。
- `slideBlob()` 在相邻两个锚点之间**线性插值**，得到一条从第一个图标滑到最后一个图标的连续轨迹。
- 锚点在 `buildDockAnchors()` 里算，**resize 和 load 都要重算**（布局一变就全错位）。探测线的 0.34 要和 `onScroll` 里算"当前栏目"的 `0.34` 保持一致，否则选框和高亮会差半格。

### 点击之后先"钉住"，而且是**滑**过去的

`pinnedSec` 记录被点中的模块：

- 点 Dock 或顶部导航的任何一项 → `pinnedSec = 该项的 data-sec`，并 `moveBlob(findDock(sec), true)` 把选框**滑动**到那个图标上。钉住期间 `slideBlob()` **直接 return**，不跟滚动走。
- **滑动是 JS 补间，不是 CSS transition。** `animateBlobTo()` 在 480ms 内按 `ease-out cubic` 从当前坐标插到目标坐标，每帧调 `placeBlob()`。**必须自己写补间**：`transform` 是逐帧写进 inline style 的，用 CSS transition 的话每一帧的新值都会把过渡重新计时，效果等于瞬移。附带好处是补间途中每帧都有位移，第 12 轮那套**速度形变会自然发生**——滑得越快拉得越长。
- **补间期间要防止被打断**，这是最容易踩的地方：
  - `slideBlob()` 的钉住分支要写成 `if(!animRaf) moveBlob(pinLink)`——否则 `onScroll`（点击引发的平滑滚动会持续触发）每帧都把选框直接摆到终点，动画根本没机会播。
  - `setActive()` 里改成 `if(on && !pinnedSec) moveBlob(a)`——否则滚动路过的栏目会把选框从被点的那一格拽走。
  - `.dock-tint` 和 `.dock-tint-inner` 的 `transform` **不能有 CSS 过渡**，否则蓝色窗口会滞后于选框、看着脱节。
- **你自己一滚动就松开**：`releasePin()` 挂在 `wheel` / `touchstart` / `touchmove` / 方向键与翻页键 / 点滚动条（`e.target === document.documentElement` 的 `mousedown`）上，并且会 `cancelAnimationFrame` 掉没播完的补间。点击带来的平滑滚动不产生这些事件，所以钉子只在你亲手滚的时候松开。
- 松开后立刻 `requestScroll()`，选框无缝接回"跟着页面滑"。

### 移动时的形变

位移和缩放合成**一条 transform** 由 JS 逐帧写进 `blob.style.transform`（内联样式优先级高于样式表，所以缩放必须写在 JS 里，不能只靠 CSS 的 `var`）：

```
translate3d(x,y,0) scale(defCur.x × bumpCur, defCur.y × bumpCur)
```

- **速度形变**：算这一帧相对上一帧的位移 `d`，方向单位向量 `(ux,uy)`，拉伸量 `s = min(d/30, .15)`。沿运动轴拉伸 `1+s`、垂直方向压扁 `1-s×.5` —— 所以**斜着滑就是斜着变形**。停下 80ms 后目标值回 `1`。
- **移动放大**：`bumpCur` 在动的时候趋近 **1.06**，停下 **360ms** 后回 1（移动中每帧重新计时，所以一直维持着）。
- 两者共用一个小缓动循环 `defTick()`（每帧 `+= (目标-当前) × .24`，收敛到 0.002 内就停 rAF），**不要给 `.dock .blob` 的 `transform` 加 CSS 过渡**，否则每帧都会被过渡拖住、看起来发黏。

相关旋钮：

- **点击滑动动画时长/曲线**：`animateBlobTo()` 里的 `dur = 380`（毫秒）与 `e = 1 - Math.pow(1-k, 3)`（ease-out cubic；想更"弹"就换成回弹曲线）
- **速度形变强度**：`s = Math.min(vd / 30, .15)` —— `30` 是"多快就到满"（越小越敏感），`.15` 是最大 15% 拉伸。**vd 是指数平滑后的速度**（`velX/velY`，平滑系数 `.35`），且**形变目标无条件由它连续决定** —— 第 23 轮教训：任何阈值（`d > .5`、`s > .004`）都会在阈值边缘一帧过、一帧不过，把目标来回扳动，选框就抖；目标归零只有一条路：`placeBlob` 停止被调用 120ms 后的定时器。移动放大的门槛同样用 `vd > .4`（平滑速度），不用瞬时 `d`
- **形变收回延时**：`placeBlob()` 里的 `defTimer` 延时 `110`（毫秒）
- **垂直压扁比例**：`s * .5` 里的 `.5`，调 0 就只拉不压
- **移动放大倍数 / 收回延时**：`bumpBlob()` 里的 `1.06` 与 `360`
- **图标变蓝的颜色**：CSS `.dock-tint-inner svg{stroke:var(--accent)}`，改 `--accent` 即可（想换回炫彩就改回 `url(#某个渐变)` 并补一个 `<linearGradient>`）
- **图标悬停颜色**：`.dock a:hover{color:var(--accent)}` —— **不要用 `--ink`（近黑）**，图标透过清玻璃选框看会是一团黑（第 23 轮用户点名）；也不要加 `translateY` 位移，图标在玻璃底下跳
- **窗口大小**：`.dock-tint` 的 `width/height`（44×44），窄屏在响应式里改成 52×44

> 改完记得**桌面端和窄屏都要看**：窄屏时 Dock 会横过来，`.dock-tint-inner` 的 `flex-direction` 和每个副本的尺寸必须跟着一起改，否则副本和真图标会错位。

## 玻璃的"真实折射 + 色散"怎么调（`GLASS_FX`）

第 21 轮加入，做法来自"位移向量图"方案（学自 Cocos 的液态玻璃教程）：

1. JS 给每块玻璃按**它自己的尺寸和圆角**生成一张位移图（canvas，RG 通道编码归一化偏移向量，128 = 不动）：形状是一个**圆角矩形透镜**——边缘处向量沿外法线最大，往中心 smoothstep 衰减到 0；
2. 一条 SVG 滤镜链：`feImage` 载入位移图 → `feDisplacementMap` 扭曲 backdrop —— **R / G / B 三个通道用三档不同的 scale 各折射一次**，再用 `feColorMatrix` 拆出各自的通道、`feComposite` 加回去 → 边缘出现色散，中心清晰；
3. 通过 `style.backdropFilter = 'url(#滤镜id)'` 挂回面板（内联覆盖 CSS 里的 `blur(0px)`）。

旋钮都在脚本里的 `GLASS_FX` 对象（搜 `GLASS_FX`）：

- **`push`**：边缘最大位移（当前 **14px**）。配合 t⁴ 衰减（见下），不用很大就有"边缘严重扭曲"的观感
- **`band`**：折射带宽 = 短边的比例（当前 .45，夹在 10~40px）
- **`sat`**：折射后的饱和度补偿（当前 1.4）
- **`sel`**：作用对象（当前 `.glass, nav, .dock, .btn.ghost`——**导航栏在内**）。想让哪块玻璃折射就加进选择器
  - ⚠️ **`.dock .blob`（Dock 选框）不能加**：这枚 44px 小选框嵌在 Dock 的 backdrop 层里、底下图标还有 hover 动画，SVG 折射滤镜采样失败会**整块渲染成深色圆片**（用户截图实锤，第 23c 轮已撤）。选框保持 CSS 原有的 `blur(0)+saturate` 清玻璃

**"越靠边越严重、中心清晰"是指数衰减给的**：位移图里每个点的强度 = `e^(k·(t−1))`（t = 1 − 离边距离/带宽，边缘 t=1、带宽外 t=0）。指数曲线的导数在边缘处取最大值 k —— **边缘"变化率"直接由 `GLASS_FX.k` 一个数控制**（当前 **5**；第 24 轮从幂函数 t⁴ 换成指数，用户点名）。想更陡/更缓就调 `k`（4 缓、7 很陡）。

**色散按 Cocos 帖的正确比例**：R/B 通道只在基础位移上做对称的 ±6% 偏移（三档 scale = base×1.06 / 1 / 0.94，base = push×2）。之前一版拉到 1/.72/.45，色散糊满整圈，被要求"大幅减轻"后收窄至此。想加/减色散改 `filterXml()` 里那两个系数。

实现细节（别踩）：

- **同样尺寸只建一次滤镜**（按 `宽_高_圆角` 缓存），面板多但尺寸少，滤镜总数也就十来个；
- **小元素（短边 < 55px）的位移会按比例压低**（`× 短边/55`，第 22 轮从 /90 放宽——之前导航胶囊只吃到七成强度，被用户看出"导航没有一样的效果"）；徽标/按钮这种矮的也不至于整片糊掉；
- **浏览器门控**：`CSS.supports('backdrop-filter','url(#f)')` 通过才启用，且排除 Firefox（解析过但渲染不支持）；不支持的浏览器什么都不做，自动回落到 CSS 里的 `blur(0px) saturate(160%)`；
- **resize 后会重跑**（280ms 防抖），尺寸/圆角变了滤镜跟着重配；`load` 时还会再跑一次（字体加载可能改变面板尺寸）；
- `backdrop-filter` 属性本身仍在（哪怕是 url() 滤镜），所以 `.liquid` 光斑需要的层叠上下文不受影响。

## 玻璃面板随滚动速度的"果冻变形"（第 22 轮）

滚动越快，所有 `.glass` 面板沿运动轴（竖向）拉伸、横向微压（最快约 **5%**），像果冻被拖了一下；停下后随速度平滑归零。实现要点：

- **形变写在独立的 `scale` 属性上，不占 `transform`** —— `.tilt`（倾斜）、`.reveal`（入场）、`.lift`（上浮）都在用 transform，谁也不能碰谁的；
- 滚动速度先做**指数平滑**（`.16`）再算形变，形变量自身再缓一层（`.18`）—— 直接拿瞬时速度会一帧一跳；
- **只作用在随页面滚动的 `.glass` 面板上**：`nav`（sticky）/ `.dock`（fixed）滚动时本来就不动，给它们变形反而突兀；
- 完全静止后清掉内联 `scale`，把属性还给样式表；
- 旋钮：`Math.min(Math.abs(v) / 34, 1) * .05` —— `34` 是"滚多快到满"，`.05` 是最大拉伸量，搜 `glassDeform`。

## 指针光感怎么调（`.liquid`）

凡是想"光跟着光标走"的元素，挂上 `liquid` 这个 class 就行。它靠三个变量控制：

| 变量 | 含义 | 当前值 |
|------|------|--------|
| `--gr` | 光斑半径，元素越大给越大 | 面板 280px · 导航 330px · 按钮 280px（第 23 轮起幽灵按钮与面板对齐）· 标签 chip 130px |
| `--ga` | 强度（透明度） | 面板 .46 · 导航 .44 · 按钮 .46（主按钮 .42）· chip .50 · Dock .44 |
| `--gc` | 光的颜色（`r,g,b`） | **默认就是 `255,250,242`（暖白）**，所有元素统一，没有单独的偏蓝覆盖了 |

例：想让导航上的光更大更淡，改 `nav.liquid{--gr:330px;--ga:.44}`。

**这团光是一盏"灯"，不是一个"圈"** —— 这是刻意调成这样的：

`::after` 的 `radial-gradient` 从中心到外**只是同一个颜色、单调递减**（`rgba(255,255,255,.95) → 白 .60 → var(--gc) .30 → var(--gc) .10 → 0`），中间**没有任何彩色色标**。所以看到的是"光标处有个光源、往四周柔柔化开"，而不是一圈蓝色光环。想调就改这条渐变的各个 stop：

- 想要更"亮心"：把 0% 那档的白提到 1，并把 16% 那档的范围缩小（比如 16% → 10%）
- 想要光更散：把 62% 那档推到 75% 以上
- 想让光偏冷/偏暖：只改 `--gc` 一个值即可（色标都是引用它的）

**两条不能动的实现细节**（动了文字就会被洗白）：

1. 光斑是 `z-index:-1`，靠"元素本身是层叠上下文"把它夹在**玻璃底和文字之间**。所以挂 `liquid` 的元素必须自己形成层叠上下文——玻璃靠 `backdrop-filter`，`.chip` 和 `.btn.primary` 是额外补的 `isolation:isolate`。**新加元素时如果它既没有 `backdrop-filter` 也没有 `isolation`，光斑会跑到整个面板后面看不见。**
2. 光斑只写 `--mx/--my` 两个变量，绘制和显隐全交给 CSS（`:hover` 时 `opacity` 0→1）。想关掉某个元素的跟随光，去掉它的 `liquid` 即可。

## 想换回深色 / 调整玻璃强度 / 关闭某些动效

所有颜色和玻璃参数集中在 `<style>` 开头的 `:root{}` 里，改这几个就够：

- `--bg`：页面底色（注意别调得太白，否则透明玻璃会跟着"消失"）
- `--ink` / `--ink-2` / `--ink-3`：正文、次要文字、弱化文字
- `--accent` / `--accent-2` / `--accent-3`：主题色（用在标题渐变、标签、Dock 高亮块）
- `--glass-bg`：**普通玻璃面板**底色与透明度。当前 `10%/2%/6%` —— 几乎全透
- `--glass-bg-strong`：**导航胶囊 / Dock / 幽灵按钮**底色与透明度。当前 `16%/5%/10%`
- `--glass-blur`：玻璃模糊强度，**这就是"磨砂感"的总开关**。当前 **`blur(0px) saturate(160%)`**（历史：34px → 18px → 7px → 0px，用户一路要求去掉磨砂，最后"模糊 + 白底全减，要完全透明"）。
  - **⚠️ blur 可以降到 0，但 `backdrop-filter` 这条属性不能删掉。** `.liquid` 的光斑是 `z-index:-1`，全靠 `backdrop-filter` 造出的层叠上下文才能被夹在玻璃底和文字之间；整个去掉 = 光斑逃到面板后面消失。`blur(0px) saturate(…)` 保留了层叠上下文，是安全的下限。
  - `saturate` 是"润"的开关，和磨砂无关：调高玻璃后面的颜色更艳、更像液态；调到 100% 就会发灰。
  - 注意 `--glass-blur` 被 **5 处**共用（普通面板 `.glass`、导航 `nav`、Dock、Dock 选框 `.dock .blob`、幽灵按钮），改一处全站一起变。只想改某一块就单独给那个选择器写 `backdrop-filter`。
  - 导航下方那片 `header::before` 磨砂是**独立**的 `blur(16px)`，不在这个变量里，要单独改（它是滚动内容划过导航时的可读性遮片，暂保留）。
  - **发雾 = 模糊 + 白底，两个要一起降。** 只降 blur 会剩下"半透明白片"的塑料感。
- `--glass-rim`：**边缘折射带，只准用冷色/无色。** 当前是一条 140° 的冷光渐变：`rgba(158,200,255,.40)` → 近无色 `.06` → `rgba(196,222,255,.20)`。
  - ⚠️ **绝对不要再往这条渐变里加暖色/粉色。** 第 10 轮那版右下角用了高 alpha 的暖粉，在浅色底上直接被看成"玻璃上有一圈红框"，被投诉了两次（第一次是"白边"，第二次是"过于明显的线条"，第三次是"红框"）。蓝色在这里读作"光"，粉色读作"边框"。
  - 两端 alpha 只给到 .40/.20 —— 再高就开始有"描了一条线"的感觉。
- `--glass-inner`：一圈极淡的漫射内光晕 `inset 0 0 30px -22px rgba(255,255,255,.55)`，加**一道**朝内的冷色折射 `inset 10px 12px 24px -20px rgba(132,178,255,.28)`（上/左）。**原来右下角那道暖粉折射已删掉**（同样是"红框"的来源之一）。玻璃的"厚度"由它表达，边上亮但完全没有线。
- `--glass-glow`：玻璃外围的光晕。当前只有本体的冷光 + 左上那一抹冷色 `-10px -12px 30px -26px rgba(132,178,255,.24)`，右下那抹暖粉已删。
- `--glass-shadow`：投影 + 上缘漫射内高光（已包含 `--glass-inner`；上缘那道白已压到 .40）
- `--radius`：圆角大小
- `--spring` / `--ease`：动效曲线

**深色主题已经做好了**（第 33 轮）：整套覆盖写在 `[data-theme="dark"]` 里，改一行 `--bg` 就能从当前的深灰蓝（`#0e1116`）换成近纯黑。深色下写死颜色的地方（背景光、光斑、导航 scrolled 态、主按钮、chip、tooltip、页脚分隔线）都单独列了一段覆盖，改浅色配方时记得两边都看。

其他常见调整：

- **调小节编号**：每个栏目标题上方的 `01`~`04` 是 `.sec-num`，改 HTML 里的数字即可；不想要就删掉那行 `<span class="sec-num">…</span>`。
- **调玻璃透明度**：改 `--glass-bg`（普通面板）和 `--glass-bg-strong`（导航/Dock/幽灵按钮）。两个数字越大越不透。嫌字看不清就调高，嫌玻璃不够透就调低。
- **觉得磨砂太重 / 想要更"清玻璃"**：降 `--glass-blur` 的模糊半径（**当前已是 0px**，没有磨砂了；想找回一点毛玻璃感就调回 8~18px）。**磨砂感和透明度是两个独立旋钮**：模糊管"看不清背后的细节"，alpha 管"透过去多少"。
- **觉得背景太花 / 太素**：调 `.orb` 的 `opacity`（当前 .40–.66）和 `--bg`。背景承担"玻璃能透出什么"的角色，太素的话透明玻璃看起来会像没渲染。
- **关掉导航下方的磨砂片**：删掉 `header::before` 那条规则。
- **调倾斜幅度**：改元素上的 `data-tilt="8"`（项目卡片），数字越大倾斜越明显，`0` 相当于关掉。
- **觉得边框还有线条感**：往下压 `--glass-rim` 两端的 alpha（现在是 `.40 … .06 … .20`，再降到 `.2` 左右就几乎看不见了）。同时把 `--glass-inner` 的负 spread 加大（现在 -22px/-20px，越负边缘光越窄越柔）。两个一起调，别只压其中一个。
- **⚠️ 玻璃上出现"红框"/暖色边**：**一定是 `--glass-rim`、`--glass-inner`、`--glass-glow` 这三处里有暖色**。它们只准出现冷蓝 或 无色（`255,255,255`）；蓝在这个浅色底上读作"光"，粉/红会被读成"边框"。搜索 `rgba(255,` 里那些 `g` 和 `b` 明显小于 230 的暖色值，全部换成 `rgba(158,200,255,…)` 或纯白即可。
- **觉得玻璃还是发雾（磨砂感）**：降 `--glass-blur` 的模糊半径，并同时下调 `--glass-bg` / `--glass-bg-strong` 里那三个白色 alpha。**发雾 = 模糊 + 白底，两个都要降才明显。** 当前基线：`--glass-bg: 10%/2%/6%`、`--glass-bg-strong: 16%/5%/10%`、`blur(0px) saturate(160%)`。
- **关掉某个动效**：删掉元素 class 里的 `tilt`（倾斜）、`liquid`（指针光感跟随）、`lift`（悬停上浮）即可，互不影响。标题的碎片化要停就把 `TITLE_FX` 那段的 `!fine` 判断去掉、或直接删掉 `.title-fx` 那个 canvas —— 标题本身是真文本，删了画布它就退回普通文字。
- **想让 Dock 选框别跟着滚动走**（退回"只在栏目切换时跳一格"）：把 `onScroll()` 里的 `slideBlob();` 注释掉即可，`setActive()` 里的 `moveBlob()` 还在，点导航和切栏目都照常。
- **换 Dock 图标**：改 `<aside class="dock">` 里的内联 SVG，用的是 24×24、`stroke:currentColor` 的线性图标，直接替换 `<path>` 就行。
- **改 Dock 转底部横条的宽度阈值**：搜索 `@media(max-width:1365px)`。
- **系统「减少动态效果」**：已适配 `prefers-reduced-motion`，用户在系统里开启后会关掉全部动画，不需要额外处理。
- **JS 被禁用时**：入场的隐藏态写在 `.js .reveal` 里，所以 JS 不可用时内容照常显示，不会白屏。—— 这是刻意留的保险，改样式时别把 `.js` 前缀去掉。

## 第 33 轮：主题 / 命令面板 / 键盘可达性

四项交互一起加，全部零依赖、仍是单文件。

**1. 深色 / 浅色玻璃主题**
- HTML 上挂 `data-theme="light|dark"`。**首帧前**就在 `<head>` 的内联脚本里定好（读 `localStorage.abto-theme`），否则会先闪一帧浅色。默认浅色，**不跟随系统**（避免"自己看着浅色、别人打开是深色"的困惑）。
- 入口两处：顶栏胶囊右侧的太阳/月亮按钮（图标表示"点了会变成什么"）、`⌘K` 面板里的「切换主题」。
- 切换用 **View Transitions** 从按钮位置做圆形扩散（`::view-transition-new(root)` + `clip-path: circle()`）；不支持的浏览器 / 开了"减少动态效果"直接瞬时切换，不做 polyfill。
- 深色下标题碎片的采样色要换一套（`sampleTitle` 里的渐变 / `sampleWord` 的填充色按主题分支），切主题后延迟 380ms 重建粒子 —— 当场重建会拖住圆扩散动画的开场。
- **跟随主题一起适配的东西**（缺一个就会出现"某处还是浅色配方"的割裂感）：
  - **指针光感**：光斑中心/中段/外圈三个颜色（`--gc-core/mid/edge`）在深色下换成冷蓝，强度再乘一个全局系数 `--ga-k`（深色 `.62`）—— 同一团白光照在深底上会变成过曝的白斑。各组件自己的 `--ga` 不用重写。
  - **投影**：浅色那套是蓝灰投影（`rgba(38,66,150,…)`），深色下一律换成更重的黑投影（nav / header.scrolled / dock / blob / ghost 按钮 / chip / project:hover / social:hover 各有一条）。
  - **背景色块 `.orb`**：浅色版那几块高明度色块铺在黑底上会浮出一层脏灰，深色下换成"更深的同色系 + 略高透明度"。
  - 其它写死颜色的地方：`header.scrolled nav` 的白底、主按钮反色（亮底深字）、chip 白膜、Dock tooltip、页脚分隔线、`@supports not backdrop-filter` 回落、主按钮的涟漪（亮底上白涟漪看不见 → 换深涟漪）。
  - `color-scheme:dark` 让原生滚动条也跟着变暗。

**2. `⌘K` 命令面板（`Ctrl/⌘ + K`）**
- 8 个条目：五个栏目 + 切换主题、复制邮箱、打开 GitHub。匹配分三档：标题开头命中 > 标题内命中 > 其它字段命中，都命中不了再退到"顺序字母"（`hel` → Hello）兜底。
- 键盘：`↑↓` 选择、`↵` 执行、`Esc` 关闭、`Tab` 被吃掉（焦点锁在输入框里，否则方向键会跑到别处）。鼠标划过也会改选中项。
- 跳转**复用 Dock 的点击**（`link.click()`）——选框钉住 + 平滑滚动那一套只有一份实现，别在这里另写一套滚动逻辑。
- 面板是 `hidden` 的，量不到尺寸、拿不到折射滤镜；打开时补一次 `glassFx.run()`。

**3. 回到顶部**
- 滚过 1.2 屏后从右下角浮出（`#totop`，玻璃胶囊）。窄屏 Dock 转到底部正中，按钮自动上移一格。

**4. 键盘可达性**
- 首个 Tab 是「跳到主内容」（`.skip`，`:focus` 时从视口上方滑下来）。
- 全局 `:focus-visible` 冷色焦点环（跟玻璃边缘同一个语言），只在键盘操作时出现。
- **没有劫持方向键** —— 方向键要留给原生滚动和 Dock 的"松钉"逻辑。

## 第 36 轮：暗色主题的"霓虹城市"风（只作用于暗色）

亮色主题一行没变 —— 所有霓虹规则都挂在 `[data-theme="dark"]` 下，`.bg .neon` 在亮色下是 `display:none`（连动画都不会跑）。

**配色**：霓虹主色 = 紫罗兰 + 品红。写成两组变量：`--neon-1/2/3`（实色，画渐变用）、`--neon-a1/a2`（rgb 三元组，拼 `rgba()` 透明度用）。暗色下 `--accent` / `--accent-2` 也换成紫罗兰 / 品红，所以链接、Dock 高亮、序号短线、进度条、logo 圆点全都跟着走。

**加了什么**：
- **背景霓虹灯池**：`.orb` 换成霓虹灯色（紫 / 品红 / 蓝各一块留呼吸感），模糊半径 80 → 96px 做泛光，透明度提高。
- **地平线网格**：`.bg .grid`，用两条极细的渐变线（竖紫、横品红）拼出 70px 网格，再压 `perspective(300px) rotateX(64deg)` + 上下渐隐遮罩。
- **霓虹光带**：`.bg .band.b1/.b2`，两道模糊 16px 的紫→品红光带。
- **缓慢呼吸**：`.bg .neon` 整体 11s 明暗循环（`.66 ↔ 1`）。
- **玻璃发光**：`--glass-shadow` / `--glass-glow` 里加了紫光晕（每块玻璃都是"被灯照着的"）。
- **边缘**：⚠️ 暗色下 `--glass-rim` **允许**带紫/品红。浅色那条"只准冷色、禁粉"的规矩只针对浅底（浅底上粉会被看成红框）；黑底上它就是灯管本身。
- **悬停＝灯亮起来**：`.glass.tilt:hover` / `.project:hover` / `.social:hover` / `.chip:hover` 泛霓虹；主按钮（亮底深字）补一圈紫光。
- **标题**：hero 背后那团光换成紫→品红，h1 加 `text-shadow` 外发光。碎片画布自己的发光见下面的「第 37 轮」。

**想调轻一点**（如果觉得晃眼或者风扇转起来）：删 `.bg .grid` 那条规则（去网格）→ 把 `.orb` 的 `blur(96px)` 改回 80px → 把 `neon-breathe` 的动画去掉（停在 `opacity:.8`）→ 最后再降 `--glass-glow` 里两个 alpha。

## 第 37 轮：标题粒子的"真发光"（辉光层 / 星火 / 光扫过）

第 36 轮之前，首屏标题的"发光"其实是**假**的 —— 靠背后那团紫光衬着，粒子自己不亮。这一轮给粒子加了真正的叠加发光。

**为什么不用 `drop-shadow` / `filter`**：那是全画布逐帧模糊，15000 颗粒子在笔记本上直接趴下。改用一个 **1/4 分辨率的离屏缓冲**：

1. 粒子照常画到主画布（清晰笔画）；
2. 同一颗粒子再按 `x/4` 画进 `bloom` 这块小画布，混合模式 `lighter`（叠加，越密越亮）；
3. 最后 `drawImage(bloom, …, 0, 0, W, H)` 放大 4 倍贴回主画布 —— **放大的双线性插值本身就是柔光**，不用额外模糊。

**三个新效果**：

| 效果 | 做法 | 调参 |
|---|---|---|
| 辉光 | 上面的叠加缓冲 | `TITLE_FX.glowDark`（暗色，默认 `.95`）/ `glowLight`（浅色，默认 `.30`） |
| 星火 | 从粒子序列等距抽 `spark` 颗，各自按随机相位闪白光 | `TITLE_FX.spark`（默认 260） |
| 光扫过 | 一道斜向白亮带缓缓掠过，乘在辉光层上（`source-atop`，只加亮"有粒子的地方"） | 扫速 `.13`、带宽 `gw*.16` |

**浅色只给一点点**：`glowLight` 默认 `.30` —— 浅底上辉光给多了会糊成一层雾。暗色才是主力，`glowDark` 想更炸就往上加。

**掉帧保护（自适应质量）**：每帧如果 >26ms 连续 12 帧，`glowWant` 归 0，辉光渐隐（收的是亮度，不是整个效果）；回到 <18ms 连续 100 帧再加回来。**另外辉光层是隔一颗粒子画的**（`(i & 1) === 0`）—— 它只有 1/4 分辨率、放大回来本来就被插值糊掉，密度减半看不出来，绘制开销却省一半；不减的话整帧绘制量翻倍，掉到 38fps 以下会被上面的保护把辉光整个关掉，等于白做。

## 用命令行部署（进阶）

```bash
# 本地初始化
cd my-site
git init
git add .
git commit -m "init site"

# 关联远程仓库（替换成你的用户名）
git remote add origin https://github.com/你的用户名/你的用户名.github.io.git
git branch -M main
git push -u origin main
```

推送后到仓库 **Settings → Pages**，确认 Source 为 `Deploy from a branch`，分支选 `main` / `(root)`，保存即可。

## 常见问题

- **打开是 404**：多半是仓库名写错了，必须严格是 `用户名.github.io`；或刚推送还没生效，等 1~2 分钟。
- **样式不对 / 显示源码**：检查 `.nojekyll` 是否上传成功，以及 `index.html` 文件名是否正确。
- **想绑定自己的域名**：在仓库 Settings → Pages 里填 Custom domain，再到你的域名服务商加一条 CNAME 记录指向 `你的用户名.github.io`。
